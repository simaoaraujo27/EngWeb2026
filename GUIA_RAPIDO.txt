🚨 VULNERABILIDADES CRÍTICAS CORRIGIDAS
════════════════════════════════════════════════════════════════════════════════

  #1: Rotas DELETE/PUT sem autenticação
      Ficheiro: api_dados/routes/userRoutes.js
      Ação: REMOVIDAS as rotas duplicadas desprotegidas (linhas 68-79)
      Resultado: Agora todas as operações requerem autenticação

  #2: Secret JWT hardcoded
      Ficheiros: auth/auth.js + routes/userRoutes.js
      Ação: Movido para .env via process.env.JWT_SECRET
      Resultado: Secret está seguro em variáveis de ambiente


⚡ VULNERABILIDADES ALTAS CORRIGIDAS
════════════════════════════════════════════════════════════════════════════════

  #3: Token em query string
      Ficheiro: api_dados/auth/auth.js
      Ação: Removido suporte a query string
      Resultado: Tokens apenas via Authorization header (Bearer)

  #4: Path traversal em upload ZIP
      Ficheiro: api_dados/routes/resourceRoutes.js
      Ação: Adicionada validação com regex /^[a-zA-Z0-9_-]+$/
      Resultado: resourceId não pode conter "../" ou outros paths perigosos

  #5: Sem autorização em DELETE de recursos
      Ficheiro: api_dados/routes/resourceRoutes.js
      Ação: Adicionado ownership check
      Resultado: Apenas proprietário ou admin pode deletar

  #6: Ratings duplicados
      Ficheiro: api_dados/controllers/postController.js
      Ação: Implementado $pull + $push para evitar duplicatas
      Resultado: Um utilizador = um rating por recurso
