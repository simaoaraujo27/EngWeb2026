[CRÍTICA #1] Rota DELETE de Utilizador SEM Autenticação
───────────────────────────────────────────────────────
Arquivo: api_dados/routes/userRoutes.js, linhas 75-79
Problema: Rota duplicada que permite DELETAR qualquer utilizador SEM autenticação

    router.delete('/:id', (req, res) => {
        User.remove(req.params.id)  // ❌ QUALQUER PESSOA PODE DELETAR QUALQUER UTILIZADOR
    });

Impacto: Um atacante pode apagar a conta de qualquer utilizador
Solução: REMOVER IMEDIATAMENTE estas 5 linhas (75-79)


[CRÍTICA #2] Rota PUT de Utilizador SEM Autenticação (Duplicada)
─────────────────────────────────────────────────────────────────
Arquivo: api_dados/routes/userRoutes.js, linhas 68-72
Problema: Rota duplicada que permite ATUALIZAR qualquer utilizador SEM autenticação

    router.put('/:id', (req, res) => {
        User.update(req.params.id, req.body)  // ❌ BYPASS DE AUTENTICAÇÃO
    });

Impacto: Um atacante pode alterar dados de qualquer utilizador (nome, filiação, etc)
Solução: REMOVER IMEDIATAMENTE estas 5 linhas (68-72)

[ALTA #1] Secret JWT Hardcoded
────────────────────────────────
Arquivos: 
  - api_dados/auth/auth.js, linha 2
  - api_dados/routes/userRoutes.js, linha 7

    const SECRET = "EngWeb2026-Projeto-Secret";

Problema: Token JWT pode ser falsificado por qualquer pessoa com acesso ao código
Impacto: Qualquer pessoa pode criar um token válido para qualquer utilizador
Solução: 
  1. Usar variável de ambiente: const SECRET = process.env.JWT_SECRET;
  2. Definir em .env: JWT_SECRET=<random-strong-secret>
  3. Nunca commitar secrets no git


[ALTA #2] Token JWT em Query String
────────────────────────────────────
Arquivo: api_dados/auth/auth.js, linha 6

    const token = req.headers['authorization'] || req.query.token;

Problema: 
  ❌ Tokens expostos em URLs (histórico de browser)
  ❌ Tokens em server logs
  ❌ Tokens visíveis em proxies e load balancers
  ❌ Tokens em referrer headers

Impacto: Tokens podem ser interceptados
Solução: REMOVER suporte a query string, aceitar apenas Authorization header

    const token = req.headers['authorization'];
    if (!token) return res.status(401).json({ message: "Token não fornecido" });


[ALTA #3] Path Traversal em Upload de ZIP
───────────────────────────────────────────
Arquivo: api_dados/routes/resourceRoutes.js, linhas 21-25

    const resourceId = req.body._id || Date.now().toString();
    const extractPath = path.join(__dirname, '../storage/resources/', resourceId);
    zip.extractAllTo(extractPath, true);

Problema: Sem validação de resourceId; pode conter "../" ou paths absolutos
Impacto: Um atacante pode sobrescrever ficheiros fora da pasta de storage
Solução: Validar resourceId com regex:

    if (!/^[a-zA-Z0-9_-]+$/.test(resourceId)) {
        return res.status(400).json({ message: "resourceId inválido" });
    }


[ALTA #4] Falta Verificação de Nível de Acesso em DELETE de Recursos
───────────────────────────────────────────────────────────────────────
Arquivo: api_dados/routes/resourceRoutes.js, linhas 128-132

    router.delete('/:id', auth.verificaAcesso, (req, res) => {
        Resource.remove(req.params.id)  // ❌ Qualquer utilizador autenticado pode deletar
    });

Problema: Sem verificação de ownership ou nível admin
Impacto: Um consumidor pode deletar recursos de produtores
Solução: Adicionar middleware de autorização que verifica proprietário/admin


[ALTA #5] Múltiplos Ratings do Mesmo Utilizador
─────────────────────────────────────────────────
Arquivo: api_dados/controllers/postController.js, linhas 24-31

    module.exports.addRating = (pid, rating) => {
        // Nota: Esta lógica pode ser melhorada para evitar múltiplos ratings do mesmo user
        return Post.findByIdAndUpdate(pid, { $push: { ratings: rating } }, ...)
    };

Problema: Um utilizador pode dar 5 estrelas 100 vezes (ou 1 estrela 100 vezes)
Impacto: Ratings podem ser manipulados artificialmente
Solução: Verificar se utilizador já votou antes de adicionar rating

[MÉDIA #1] Falta Proteção CSRF na Interface
─────────────────────────────────────────────
Arquivo: interface/app.js
Problema: Sem middleware CSRF (csurf)
Impacto: Um site malicioso pode fazer requisições em nome do utilizador
Solução: Adicionar csurf middleware

    const csrf = require('csurf');
    app.use(csrf());


[MÉDIA #2] Cookies Sem Flags de Segurança
──────────────────────────────────────────
Arquivo: interface/routes/index.js, linhas 270-271

    res.cookie('token', response.data.token);  // ❌ Sem flags de segurança

Problema: Cookie acessível a JavaScript (XSS), não usa HTTPS, sem SameSite
Solução:

    res.cookie('token', response.data.token, {
        httpOnly: true,      // Impede acesso JavaScript
        secure: true,        // HTTPS only
        sameSite: 'strict'   // CSRF protection
    });


[MÉDIA #3] Sem Validação de Inputs
──────────────────────────────────
Arquivo: Todo o projeto
Problema: Sem validação de posts, comentários, hashtags, tipos, etc
Impacto: XSS, injeção MongoDB, dados inválidos
Solução: Usar express-validator ou joi para validação

    const { body, validationResult } = require('express-validator');
    
    router.post('/', [
        body('titulo').trim().notEmpty().isLength({ max: 200 }),
        body('conteudo').trim().notEmpty(),
        auth.verificaAcesso
    ], (req, res) => { ... });


[MÉDIA #4] NoSQL Injection em Query Parameters
───────────────────────────────────────────────
Arquivo: api_dados/routes/resourceRoutes.js, linhas 91-98

    if (req.query.tipo) Resource.listByType(req.query.tipo)

Problema: req.query pode conter objetos MongoDB: ?tipo={$ne: null}
Solução: Validar que tipo é string


[MÉDIA #5] Erro Expõe Informações Sensíveis
───────────────────────────────────────────
Arquivo: Múltiplos (userRoutes, resourceRoutes, etc)

    res.status(500).json({ error: error.message, message: "..." })

Problema: error.message pode conter stack trace ou informações de BD
Solução: Registar erro server-side, retornar mensagem genérica ao cliente

    console.error('Database error:', error);
    res.status(500).json({ message: "Erro no servidor" });


[MÉDIA #6] Falta Limite de Upload
──────────────────────────────────
Arquivo: api_dados/routes/resourceRoutes.js, linha 10

    const upload = multer({ dest: 'uploads/' });  // Sem limite!

Problema: Um atacante pode fazer upload de ficheiros gigantes (Zip bomb)
Solução:

    const upload = multer({ 
        dest: 'uploads/',
        limits: { fileSize: 500 * 1024 * 1024 }  // 500MB max
    });


[MÉDIA #7] JSON.parse Sem Try-Catch
────────────────────────────────────
Arquivo: interface/routes/index.js, várias linhas

    res.locals.user = JSON.parse(req.cookies.user);

Problema: Se cookie for malformado, a aplicação crasheia
Solução:

    try {
        res.locals.user = JSON.parse(req.cookies.user);
    } catch (e) {
        res.locals.user = null;
    }

[BAIXA #1] Sem Rate Limiting
─────────────────────────────
Problema: Login endpoint vulnerável a brute force
Solução: express-rate-limit

    router.post('/login', 
        rateLimit({ windowMs: 15 * 60 * 1000, max: 5 }),
        ...
    );


[BAIXA #2] CORS Muito Permissivo
─────────────────────────────────
Arquivo: api_dados/app.js, linha 13

    app.use(cors());  // Aceita qualquer origem

Solução: Configurar origens permitidas

    app.use(cors({ origin: process.env.ALLOWED_ORIGINS }));
