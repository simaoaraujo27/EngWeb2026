🚀 COMO USAR
═══════════════════════════════════════════════════════════════════════════════════

  OPÇÃO 1: Usando Makefile (Recomendado)
  ────────────────────────────────────────

  make up                 # Iniciar desenvolvimento
  make logs              # Ver logs
  make restart           # Reiniciar
  make down              # Parar
  make secrets           # Gerar novos secrets
  make help              # Ver todos os comandos


  OPÇÃO 2: Usando Docker Compose Diretamente
  ────────────────────────────────────────────

  Desenvolvimento:
  $ docker-compose up -d
  $ docker-compose logs -f
  $ docker-compose down

  Produção:
  $ docker-compose -f docker-compose.prod.yml up -d
  $ docker-compose -f docker-compose.prod.yml logs -f
  $ docker-compose -f docker-compose.prod.yml down


  OPÇÃO 3: Gerar Novos Secrets
  ────────────────────────────

  $ bash generate-secrets.sh
  
  Isto cria arquivo temporário com values aleatórios:
  - JWT_SECRET (32 bytes)
  - MONGO_PASSWORD (24 bytes)

  Copie para .env.docker.production

🧪 TESTES RÁPIDOS
═══════════════════════════════════════════════════════════════════════════════════

  1. Iniciar Containers
     $ make up
     # ou
     $ docker-compose up -d

  2. Verificar Status
     $ make ps
     # ou
     $ docker-compose ps

  3. Testar API
     $ curl http://localhost:16000/health
     # Resposta: {"status":"OK"}

  4. Testar Interface
     $ curl http://localhost:16001
     # Deve retornar HTML

  5. Ver Logs
     $ make logs
     # ou
     $ docker-compose logs -f

  6. Parar Tudo
     $ make down
     # ou
     $ docker-compose down


⚡ COMANDOS ÚTEIS (Makefile)
═══════════════════════════════════════════════════════════════════════════════════

  make up                # Iniciar containers
  make down              # Parar containers
  make restart           # Reiniciar
  make ps                # Ver status
  make logs              # Ver logs
  make build             # Rebuild imagens
  make rebuild           # Clean rebuild
  make clean             # Remove containers + volumes
  make clean-all         # Remove tudo (containers, volumes, images)
  make secrets           # Gerar novos secrets
  make shell-api         # Shell no container API
  make shell-interface   # Shell no container Interface
  make shell-mongo       # Shell no MongoDB
  make prod-up           # Iniciar produção
  make prod-down         # Parar produção
  make prod-logs         # Logs de produção

🔐 PRODUÇÃO - PASSOS IMPORTANTES
═══════════════════════════════════════════════════════════════════════════════════

  1. GERAR SECRETS
     $ bash generate-secrets.sh
     
  2. EDITAR .env.docker.production
     - JWT_SECRET com valor do passo 1
     - MONGO_PASSWORD com valor do passo 1
     - ALLOWED_ORIGINS com domínios reais
     - COOKIE_SECURE=true
     
  3. NUNCA COMMITAR
     - .env.docker.production
     - .env.docker.secrets
     - Qualquer arquivo com secrets
     
  4. USAR GERENCIADOR DE SECRETS
     - Docker Secrets (Swarm)
     - Kubernetes Secrets
     - HashiCorp Vault
     - AWS Secrets Manager
     
  5. BACKUP STRATEGY
     - MongoDB data volumes
     - Ficheiros de uploads
     - Configurações
